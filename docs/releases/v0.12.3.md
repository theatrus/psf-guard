# v0.12.3

PSF Guard 0.12.3 adds project and plan cleanup, lets you leave collaborations, and improves color-stack processing, star colors and large-file downloads.

## Upgrading

- **Allow time for rebuilds.** The stacking engine changed, so each stack
  rebuilds once when next opened or refreshed. Color previews that use
  deconvolution or RC-Astro also become out of date; build them again to use
  the corrected processing order and orientation. If a channel card still
  shows an upside-down RC-Astro result, apply its processing again.
- **Existing color previews keep their settings.** New previews follow each
  channel card's deconvolution and RC-Astro choices. To use that behavior in
  an existing preview, choose **From each channel card** under
  **Deconvolution and RC-Astro**.
- **Update the N.I.N.A. plugin for project deletion.** Deleting a project on
  a rig needs a plugin version with project deletion support. Older plugins
  keep the rig's project. Sync keeps projects with captured frames or
  collaboration assignments in the destination.
- **Upgrading from 0.11:** read the
  [0.12 upgrade notes](https://github.com/theatrus/psf-guard/blob/v0.12.3/docs/releases/v0.12.0.md#upgrading-from-011),
  including the Target Scheduler deprecation. Your current connection still
  works in 0.12. For new databases, use **Settings → Databases → Import from
  Target Scheduler**. A later update will create a PSF Guard catalog for you
  and keep captures, plans and grades in sync with Target Scheduler.

## Organize projects and targets

- Move a target to another project in its database, or create a project for
  it. In Library, click **Edit** beside the target, then **Move to another
  project...** and **Preview move**. Exposures, exposure plans and stack
  previews move together. A new project copies the original project's
  settings and starts **Inactive**.
- A target without captured exposures can move between Target Scheduler
  profiles. Its exposure plans use matching templates in the destination
  profile or copies of their existing templates. Targets with exposures must
  stay in the same profile. Use **Merge target** if the destination already
  has a target with the same name.
- Under **Archived projects**, **Reopen** returns a project to the Library
  as **Inactive**. Set it **Active** when you want Target Scheduler to use it.
  A plan with nothing captured also has **Reopen** when it is Closed on any
  rig; it sets the project Inactive on each of those rigs.
- **Edit project → Delete project...** previews the records to remove. Type
  the project's name to confirm if it has frames. Deleting removes catalog
  records, grades and measurements; **image files stay on disk**. A linked
  plan keeps its framing and other databases but stops planning for that rig.
  Deletion needs an editor account and a server started with
  `--allow-database-management`.
- Imports and sync skip deleted projects until you choose **Allow again**
  under **Deleted projects**. A deleted project with no frames appears there
  once a sync has skipped it. A returning project gets its own plan; use
  **Attach a project from another database** to rejoin its previous plan.
- Under **Plans with nothing captured yet**, the delete button previews the
  linked projects. **Delete plan** removes those projects, the plan and its
  framing. For a plan with captured frames, delete its projects in Library
  first. Deleting a collaboration plan also leaves the collaboration.

See [Planning and the Library](https://github.com/theatrus/psf-guard/blob/v0.12.3/docs/DIRECTOR.md).

## Sync deleted projects and recover refused uploads

- Pulls, planning pushes and sync with another PSF Guard server running this
  version now carry project deletions. The preview and result show the
  deletion count. A destination project with frames or collaboration work
  stays; the preview shows its captured exposure count. A peer pull deletes
  only projects listed in its preview.
- **Allow again** also carries across syncs. A catalog that received your
  deletion no longer deletes the project again after you allow it back.
- Uploads for deleted projects or removed rejects are refused with recovery
  instructions. An updated N.I.N.A. plugin holds them without retrying.
  After allowing the project back or restoring the reject, choose **Retry
  refused uploads**. **Forget refused uploads** removes those queue entries
  while keeping image files. Older plugins show blocked jobs. Another
  capture with the same file name can still upload.

See [Importing and sync](https://github.com/theatrus/psf-guard/blob/v0.12.3/docs/IMPORTING.md).

## Leave a collaboration

- In an imported plan's **Activation → Collaboration assignments**, click
  **Leave collaboration**. PSF Guard ends open assignments in writable rig
  databases, removes imported assignments, cancels unfinished file transfers
  and stops nightly intake for that project.
- **Send pending reports with Check in first.** Leaving deletes unsent
  reports. Reported frames lose their protection from reject removal and
  project deletion. Project deletion still keeps image files on disk.
- Your local plan, framing, exposure plans, rig projects, frames and grades
  stay. Target Scheduler targets remain scheduled until you change them.
  The next activation uses your plan's framing instead of collaboration panels. You can edit the plan as your own. Joining and importing again later
  rejoins the same plan.
- PSF Guard declines coordinator tasks for signed-in rigs. The dialog lists
  rigs that are not signed in; leave or decline their project on the
  coordinator's site too. If a linked database is missing or not writable,
  its assignments stay open until you register it again and activate the plan.
- A plan with frames in collaboration reports cannot be deleted until you
  leave the collaboration.

See [Collaboration](https://github.com/theatrus/psf-guard/blob/v0.12.3/docs/DIRECTOR.md#leave-a-collaboration).

## Process channel and color stacks

- New color previews follow each channel card's deconvolution and RC-Astro
  settings, including after automatic rebuilds. Input lanes list the steps
  used, and changes on a card mark the color preview out of date. Choose
  **Set in this build** to set tools per input instead; it starts from the
  cards' current choices.
- Each input's tools run on its own stack before background extraction and
  alignment. Channel cards and color previews reuse matching results.
  Changing background extraction or a stretch no longer reruns those tools.
- In **Processing stack**, **RC-Astro on the color channels together** runs
  BlurXTerminator and NoiseXTerminator on aligned channels before color
  calibration and stretching. It is off by default. BlurXTerminator starts
  in **Correct only** mode to correct star shapes and color fringes without
  sharpening; NoiseXTerminator reduces color noise. Changes to calibration,
  crop or stretch reuse the results. All BlurXTerminator sections now offer
  **Correct only**.
- BlurXTerminator, NoiseXTerminator and StarXTerminator keep stacks without
  row-order metadata, including WBPP masters, the right way up.
- Returning to **Stacks** restores a mono processing run's progress.
  **Apply processing** stays disabled until it finishes.
- Color build failures explain the problem, such as a missing RC-Astro
  installation or license. The message appears beside **Apply processing
  stack** when you started the build there, and at the top of the card otherwise.

See [Stack processing](https://github.com/theatrus/psf-guard/blob/v0.12.3/docs/STACKING_PREVIEWS.md#deconvolution-and-rc-astro-on-color-inputs).

## Build stacks and download files

- The final **Rejecting transients** pass reads each frame once instead of
  three times and uses less memory. Temporary files in `stack-scratch`
  below the stack folder need four bytes per sample per frame and are removed
  afterward. With too little disk space, the pass uses the previous
  three-read method. Progress shows reading and integrating stages.
- Color calibration keeps clipped star cores neutral instead of tinting
  them cyan or blue, in one-shot-color, RGB, LRGB and narrowband stacks.
  Existing stacks gain the clipping data when they rebuild.
- Large-file downloads, including stack FITS, calibration masters, backups
  and WBPP files, use larger reads to reduce streaming overhead.

## Other fixes

- Restoring a reject returns it to its target's current project. If the
  target was merged, the frame returns to the destination target. Restoring
  rejects does not recreate frames in a deleted project.
- **Merge target** removes the old target's stack previews.
- An invalid target edit, such as an RA of 25 hours, leaves every field
  unchanged instead of saving the name alone.
- With no grace period, a reject recorded during a removal preview is
  eligible immediately instead of briefly appearing too new to remove.
