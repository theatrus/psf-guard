# v0.12.5

PSF Guard 0.12.5 keeps renamed files' frames in catalogs that a sync writes, and lets you merge frames imported twice there too.

## Fixes

- A catalog that syncs from Target Scheduler, or that rigs sync their lights
  into, now keeps a renamed file's frame too. 0.12.4 left such catalogs out,
  because every sync sends the name N.I.N.A. wrote again: an import there
  still added a renamed file as a second frame, and **Settings** did not
  offer **Merge renamed lights** for them. PSF Guard now remembers the names
  it changed. A sync that sends the old name leaves the new one in place, and
  a peer that pulls the catalog gets the old name, which its own copy of the
  file has. When a sync sends some other name, the file was renamed where it
  came from, and that name is used. To clean up frames imported twice, open
  the database in **Settings** and click **Merge renamed lights**. PSF Guard
  copies the database first.
  See [Renamed files](https://github.com/theatrus/psf-guard/blob/v0.12.5/docs/IMPORTING.md#renamed-files).
  ([#1020](https://github.com/theatrus/psf-guard/issues/1020))

- While one of a database's image folders is missing, **Settings** names the
  folder under the database. The renamed-lights check waits until the folder
  is back. Before, the check stayed hidden without saying why.
