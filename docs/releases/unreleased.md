# Unreleased

> these entries into `vVERSION.md`, adding to that file if it already exists.
> Then reset this file. See [the release guide](../RELEASING.md).

## Changes

- **Director tolerates clock differences:** With the matching Director plugin update, local safety and recovery checks no longer fail because the observing PC and PSF Guard server have different clock offsets. Assignment windows still follow the server clock; local safety freshness and shutdown deadlines keep their original limits.

- **Activate rigs whose database has leftover rows:** The activation preview no longer fails with *Its database could not be read: FOREIGN KEY constraint failed.* on a rig database that holds rows from a deleted project, such as its rule weights. PSF Guard leaves those rows alone.
- **Faster Nights and Live:** **Rigs › Nights**, **Night details** and Live's **Tonight** column load many times faster. With four rigs and three dozen targets on each, a week of nights takes about 0.5 s instead of 11 s, a month about 1.5 s instead of 45 s, and tonight about 0.1 s instead of 1.3 s. The first time PSF Guard plans a night at a site, it takes longer, up to about 6 s for a month, while it works out that night's sky. It keeps each sky, so later requests take the shorter times. The nights and schedules are the same as before.
- **Request replacement Director flats:** The Calibration page's **Flat coverage** tab, formerly **Scheduler flats**, lists Director flat batches next to Target Scheduler's. Invalidate a suspect batch to ask for new flats; PSF Guard keeps the image files. This needs the Director plugin update that adds **Director Flats**, which also takes flats for plans whose light frames are done.
- **Steady weather on Live:** On **Rigs › Live** and **Rig setup › Weather**, N.I.N.A.'s reported cloud cover and the forecast no longer switch between *cloudy* (or *clear*) and *unknown or stale* every few seconds when this computer's clock differs from the server's. The report's age and **Forecast fetched** read true, too.
- **The Director plugin uploads its frames:** With the matching PSF Guard Director update, the frames Director captures go to the rig's database, exactly as the Sync plugin's uploads do: the same receive folder, folder layout, import and calibration matching. **Rig setup › Plugins** now has separate cards for **PSF Guard Sync**, **Image uploads** and **PSF Guard Director**. **Image uploads** serves both plugins and turns on without a Sync pairing, so a Director-only rig can use it. Live's **History** lists Director uploads too.
- **See every rig on Live, Target Scheduler rigs included:** **Rigs › Live** has six columns: Rig, Now, Weather, Plugins, Projects and Tonight.
  - Each rig's link state sits under its name. Any call from the Director or Sync plugin, including an image upload, keeps the rig **Online**.
  - A database used only by the Sync plugin appears without opening Planning first.
  - With the updated PSF Guard Sync plugin, **Now** shows what N.I.N.A.'s sequence is doing: the exposure and its count, autofocus, a slew, a wait and when it ends. It also shows when the last frame, dither and autofocus happened.
  - **Plugins** lists the plugins that have called. A refused or failed Sync action shows in red until the same work succeeds; a stream of uploads never hides a refused merge. **History** opens the rig's recent plugin actions and when each plugin last called.
  - **Projects** counts the Active projects in the rig's database, Target Scheduler and Director alike, and opens them in the Library.
  - **Now** leaves out "reconciliation required", which older Director plugins added to a stopped session. Nobody had to act on it: the plugin and PSF Guard settle the session's work at its next check-in. Current Director plugins no longer send it.
  - **Weather** marks each rig's lines **Observed** (from N.I.N.A.) and **Forecast** (the site's), each label on its own line above the value, and shows *No weather* when there is none. The forecast providers are credited once, below the table; hover a line to see its sensor or provider.
- **Find and activate plans that need it from the Library:** **Show › Needs activating** lists plans whose rigs lack what you saved in Planning. That covers a plan never activated, a plan or framing saved since the last activation, a rig left out, a remote site that has not received the last activation, and Target Scheduler rows changed since the last activation, such as a goal, exposure or template edited in N.I.N.A. Each plan shows a **Needs activating** pill, and its **Activate** button opens the activation preview without leaving the Library. Plans imported from Target Scheduler and not edited in Planning are not listed. A plan activated before this update is checked for Target Scheduler changes only after its next activation. After this update, older PSF Guard versions cannot open the planning store.
- **The Library keeps its filters:** **Sort** now lives in the URL with Database, Show and the search. All four survive a trip to a plan and back. When a link opens the Library without filters, it restores the last ones set in that browser tab, except on a link back to a project. When the header shows **All projects** for one database, the Database filter shows the same database, and changing the filter moves the header with it.
- **Plans on a second rig appear in the Library:** With the Database filter set to a rig, **Plans with nothing captured yet** now lists a plan activated on that rig before the rig has a frame for it. Before, a plan another rig had frames for appeared nowhere under that filter. The header's project picker lists the same plans under **Plans waiting for frames**, with the rigs that have no frames, so you can open their workspace from any page. That section replaces **Plans without a database**, whose plans it still lists.
- **Sync plugin rigs count as exposing:** The **Rigs** tab's count, such as `2 rigs · 1 exposing`, now counts a rig whose PSF Guard Sync plugin reports an exposure, not only rigs running the Director plugin. The Sky's **Live** view marks and places those rigs at the target they are exposing, and **Night details** shows what N.I.N.A.'s sequence is doing tonight. Pages other than **Live** and **Rig setup** now poll a much smaller rig summary, and the server answers it and **Live** from memory, so an open tab no longer makes the server open every rig's database every 15 seconds.
- **Edit site weather from Rig setup:** The **Weather** tab on **Rig setup** has an **Edit site weather** link. It opens the rig's planning site under **Settings › Presets › Sites**, ready to change its forecast, cloud limit and dew limit.
- **Faster catalogs while background work runs:** A catalog on a local disk now uses SQLite's write-ahead log, so grading, imports and Sync no longer wait while previews, exports or background passes read it. Two files ending in `-wal` and `-shm` now sit beside the catalog while PSF Guard runs; keep them with it. A catalog on a network share keeps working as before.
- **See which N.I.N.A. plugins are on:** **Rig setup › Plugins** opens with **Plugins on this rig**, which shows each plugin **On** or **Off** and what it does. The Sync plugin's panel now works like the Director plugin's: **Pair**, **Scheduler sync**, **Image uploads** and **Remote API key**. Scheduler sync and image uploads each have **Turn on** or **Turn off**, which applies at once. The **Edit remote receive and pairing** form is gone, and so are the refresh buttons: the page reads the rig again when you come back to it.
- **Flats from the same night beat an old flat master:** With external masters on **Whenever one matches**, a night that has its own raw flats but no master from that night now builds a master from those flats when every external master is past the **Flat age limit**. Before, it took the nearest external master even when that master was weeks away, and the calibration report then marked its lights as unable to be calibrated. A master within the limit is still used first.
- **Activate a new rig before it has images:** A plan now activates on a new rig with no frames and no plugin. The updated PSF Guard Sync plugin adds the project to the N.I.N.A. profile you have open on its next pull, so a rig with two profiles no longer gets the wrong one. Older plugins keep working: PSF Guard sends them the project under the profile they last reported. Pair each N.I.N.A. profile with its own PSF Guard database. When one database already holds two profiles, Director now plans for the profile its plugin reports instead of the one with the most projects.
- **Remove a rig:** **Remove** now appears beside each database under **Settings › Databases & rigs**, and on its **Rig setup** tab. The dialog lists what goes. Removing deletes the rig's settings, Director history and pairing, and takes the rig out of its plans; you cannot undo this. The database file and images stay on disk, and a rig with open work must close it first.
- **Both N.I.N.A. plugins on Rig setup:** Pair the PSF Guard Sync plugin, and choose what the database accepts from it, under **Rig setup › Plugins**, beside the Director plugin. Without planning, **Rig setup** shows only the Sync plugin. The **Sync** page keeps Target Scheduler sync and transfers, and **Open Rig setup** links to the plugin. Saved settings, pairings and plugin connections are unchanged.
- **Check a rig's filters without the Director plugin:** Type a rig's filter names under **Rig setup › Optics › Filters**, or copy the names its templates and frames already use. The plan editor and the activation preview warn when a template uses a filter that isn't on the rig, before N.I.N.A. tries to shoot it. The template library suggests your rigs' filter names as you type.
- **See which Sync plugins are current:** Each paired Sync client now shows when it last connected and its plugin version. A note identifies a client whose plugin is too old to add new projects to its N.I.N.A. profile itself.
- **Find plans with nothing captured:** The Library links to these plans from the top of its list. A Database filter now offers plans that are on no rig.
- **Start Director without manual recovery:** Paired equipment reports apply automatically and preserve work permission and plan selection. With the matching Director plugin update, interrupted assignments retire automatically after the plugin confirms idle equipment. Saved images and receipts remain available, and fresh work uses current image counts. On a rig with two paired plugins, only the plugin allowed to take work updates the equipment.

- **Run a rig with the Director plugin:** Rig setup has a new **Plugins** tab. Generate a pairing code, see the equipment the plugin reports automatically, manage work permission and follow its work without calling the API.
- **Use Director and Sync on one rig:** Both plugins can stay active. Changing a rig's **Mode** keeps both pairings, the accepted equipment and the allowed work, so you can compare the two. Pairing Director no longer switches a rig set to Target Scheduler.
- **Run plans whose templates use the camera default:** Director uses the default gain and offset reported by N.I.N.A. for templates left at `-1`. Update PSF Guard Director and run the session to report those defaults automatically.
- **See when no plan can run:** The **Plugins** tab no longer says work is allowed when no activated plan can run. It lists why each plan was left out, and tells you how to start a session.
- **Trust a Director rig's night load:** The Nights page counts only the plans activated on a Director rig, and shows **Full** instead of large overbooked hours from targets that overlap.
- **See why a rig gets no work:** The **Plugins** tab explains when work is off, a plugin was removed or an activated plan cannot run. Equipment and setup updates preserve work permission.
- **Recover a stuck rig:** When a plugin is removed while it holds work, **Close work** lets the rig take work again. Attempts it reported stay spent.
- **Clearer pairing codes:** **Generate pairing code** is now **Generate Sync pairing code**, and the Sync tab shows where Director pairs.
